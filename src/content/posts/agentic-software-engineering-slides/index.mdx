  <section class="slide" data-slide="phase-04" aria-label="Phase 04 — Features">
    <div class="stack">
      <span class="eyebrow">Phase 04 · Features</span>
    </div>
    <div class="stack stack--lg" style="max-width: 1200px;">
      <h2 class="headline headline--lg">Turn screens into contracts</h2>
      <ul class="bullets">
        <li>Map the <strong>dependency graph</strong>. Two tickets touching the same data contract are not independent.</li>
        <li>Cut into <strong>vertical slices</strong> that can be demonstrated and tested independently.</li>
        <li>Write for a competent stranger with no memory — that's the actual execution condition.</li>
      </ul>
      <hr class="rule" />
      <p class="pullquote">
        Could a fresh session with no conversation history produce the intended result from this ticket and its linked canonical artefacts?
      </p>
    </div>
    <div></div>
  </section>

  <section class="slide" data-slide="phase-05" aria-label="Phase 05 — Spec and ticketing">
    <div class="stack">
      <span class="eyebrow">Phase 05 · Spec &amp; ticketing</span>
    </div>
    <div class="stack stack--lg" style="max-width: 1200px;">
      <h2 class="headline headline--lg">The issue tracker is the agent's external memory</h2>
      <ul class="bullets">
        <li>Freeze the plan. Step away. Read it <strong>end-to-end</strong> — some errors live <em>between</em> tickets.</li>
        <li>One ticket, one bounded context. Do not feed forty tickets into one session.</li>
        <li>Publish with an <strong>idempotent</strong> script: draft / published / closed — recoverable from failure.</li>
      </ul>
      <hr class="rule" />
      <p class="footer">
        Persist the remote issue number. Re-running the synchroniser should update
        the intended issue, never create a duplicate.
      </p>
    </div>
    <div></div>
  </section>

  <section class="slide slide--split" data-slide="phase-06" aria-label="Phase 06 — Build">
    <div class="stack">
      <span class="eyebrow">Phase 06 · Build</span>
      <h2 class="headline headline--lg">Now — and only now — implementation begins</h2>
      <ul class="bullets">
        <li>Per-ticket loop: <strong>requirement → implement → commit → PR → review → fix → merge</strong>.</li>
        <li>Parallel by design — bought in Phase 04, not free. Worktrees materialise it.</li>
        <li>Three-tier agent authority: <strong>allowed / needs approval / never</strong>.</li>
      </ul>
      <p class="footer">
        PRs carry evidence, not claims. Commands, results, screenshots, traces,
        risks, rollback. No side channel for quick fixes to main.
      </p>
    </div>

    <div class="stack">
      <span class="eyebrow">Phase 07 · Ship</span>
      <h2 class="headline headline--lg">Shipping is a hypothesis</h2>
      <p class="body body--secondary" style="font-style: italic;">
        Before deploy, write down:
      </p>
      <ul class="bullets">
        <li>Which metric should move?</li>
        <li>What error rate is acceptable?</li>
        <li>Which signal shows a regression?</li>
        <li>What is the rollback, in one sentence?</li>
      </ul>
      <p class="footer">
        Instrument with the feature, not after. Correlate traces, metrics, and logs
        with the release and with the acceptance criteria.
      </p>
    </div>
