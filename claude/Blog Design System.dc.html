Why Substack rasterizes your tables, and what it costs you

28 July 2026

A ten-column benchmark matrix is the most useful artifact a performance post can contain. Turned into a PNG it is unselectable, unsearchable, unreadable by a screen reader, and invisible to every model that will ever summarize your work.

The rest of this page is a specimen: it exists so that every element that can appear in a post has been decided once, in the stylesheet, rather than negotiated per post in raw HTML. Body text sits at a 68ch measure — roughly seventy-five characters with this face at 17px — and everything data-bearing is allowed to escape it.

Headings and prose #

Headings are set in the UI face, not the body serif. The mix is deliberate: a sans heading reads as structure and a serif paragraph reads as voice, and at 3,000 words the distinction is what keeps scanning possible. Links look like an unvisited link, and once followed they look like a visited link — same weight, shifted hue, because losing your place in a long list of references is worse than a little chromatic variety.

Third level, for steps inside an argument #

Inline code such as prefers-color-scheme or --table-header-bg carries a hairline border so it survives inside a link and against the table-header fill without ambiguity.

Fourth level, effectively a run-in label #

Below fourth level, use a paragraph with a bold lead-in instead. Nesting past four levels means the post wants splitting.

  • Unordered lists use a square marker in the faint token.
  • A nested level indents once and no further:
    • Second level, same marker at the same size.
    • The list never becomes an outline.
  • Item spacing is tighter than paragraph spacing.
  1. Ordered markers are set in mono so multi-digit numbers stay aligned.
  2. Useful for procedures, which is most of what this blog publishes.
    1. Nested ordered lists switch to lower-alpha automatically.
    2. Same rule: one level of nesting only.
  3. Numbers are not decoration — they mean order.

Code blocks #

workers/cache.ts 
export default {
  async fetch(req: Request, env: Env, ctx: ExecutionContext) {
    const cache = caches.default;
    const key = new Request(new URL(req.url).toString(), req);

    let res = await cache.match(key);
    if (res) return res;

    res = await fetch(env.ORIGIN + new URL(req.url).pathname, { cf: { cacheEverything: true, cacheTtlByStatus: { "200-299": 300, "404": 1, "500-599": 0 } } });

    res = new Response(res.body, res);
    res.headers.set("cache-control", "public, s-maxage=300, stale-while-revalidate=86400");
    ctx.waitUntil(cache.put(key, res.clone()));
    return res;
  },
};

The cacheTtlByStatus line overflows deliberately: code blocks scroll horizontally rather than wrap, because a wrapped line in a shell transcript is a different command.

03 · Dark mode — designed, not inverted

Same tokens, different values #

The dark surface is a lifted slate, not near-black: at 3,000 words a pure black field makes serif stems bloom. Body text sits at 0.882 lightness rather than pure white for the same reason — at 0.925 it halates over a long read. Links such as this one lift in lightness to hold AA against the darker field, and visited links keep the hue shift.

08 · The five hard cases

Body text is now 19px at every width; the row rule is --table-rule at L 0.932, three steps lighter than --border, so ten dense rows stop reading as stripes.

1 · ten columns, long cells, 380 viewport — actual size, scrollable

Drag the table sideways in the frame. Three affordances stack: the pinned Provider column with its 1px shadow, the thin styled scrollbar, and an edge tint that recedes as you reach each end — the tint is background-attachment: local, no JS. Cells wrap; nothing shrinks, nothing breaks mid-word.

2 · 1920 viewport, 40% scale — --bleed-max holds at 1280

At 1920 the bleed stops at 1280 and centres with the measure, leaving 320px of quiet surface either side. Columns size to content rather than stretching, so the numbers stay in scanning range of their headers.

export const pool = new Pool({ connectionString: env.DATABASE_URL, max: 1, idleTimeoutMillis: 0, connectionTimeoutMillis: 5_000 });

export async function q(sql, params = []) {

09 · How the two bold decisions work

The full-bleed break

.page is a four-track grid: gutter | measure | gutter, capped at 1280px and centred. Children land in measure; .bleed spans full.

No 100vw and no negative margins, so it can never cause horizontal page scroll and is immune to scrollbar width. It is one class on one wrapper div — safe to type in markdown.

At 1440px the break is 1280px wide, symmetric around the measure. At 768px and below the gutters collapse to 20px, so the break is effectively edge to edge; at 380px the data gets all 380 pixels, and the top and bottom edges of the block are marked with a strong hairline rather than a card.

The table treatment

Headers: UI face, uppercase, 0.02em tracking, filled with --table-header-bg and closed with a 2px rule — the only place in the design where a fill and a heavy rule are allowed.

Rows: hairline separators plus a 1.4%-lightness zebra. Numeric cells are mono, right-aligned, tabular-nums; the best value in a column takes a 5px accent dot, never a coloured background.

At 380px a 10-column table scrolls horizontally inside .table-scroll. The first column is position: sticky so the row label never leaves. Affordances: a thin styled scrollbar, an edge tint that recedes when you reach each end (pure CSS, background-attachment: local), and a mono note under the table. Text size is identical to desktop.
